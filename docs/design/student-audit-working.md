# Student UI source audit — working notes

Date: 2026-10-26. Scope: `/intern` and its 22 other page routes. Source audit only; no browser interaction, runtime result, or completion claim is made here. The parent task owns browser captures and shared design tokens. Public homepage `/` is preserved.

## Baseline and design constraints

- Next.js 16.4.2 App Router, React 19.2.3, Tailwind 4.1.18, Framer Motion 12.26.2 and Lucide 0.525 are already installed. No extra motion or icon dependency is needed.
- Read project-local Hallmark `SKILL.md` and `references/redesign.md`, Impeccable `SKILL.md`, `reference/critique.md` and `reference/operate.md`. Impeccable context was run once by the parent, so it was not rerun here.
- This is an **Operate** surface: the signature is an accurate view of current placement and next work, rather than a decorative hero. Use one light-blue/navy system, semantic state color only, precise compact typography, grouped surfaces and list/table layouts.
- The lifecycle is source truth: recruitment first, passed/unassigned, assigned/active, and assignment history. Read-only outcome access after a placement ends must stay available.
- Route wrappers mostly delegate to `components/product`. Editing only `components/intern` would leave much of the actual UI unchanged.
- `app/intern/layout.tsx` owns persistent `InternEntry`, with an onboarding exemption. `InternEntry` detects existing context and must not mount another guard/shell. `intern-workspace-context.tsx` keeps drafts and focus during revalidation.
- Current style cascade: `student-experience.css` (3,047 lines) → `workspace.css` (1,602 lines at inspection) → `aurora.css` (326 lines at inspection). Source comments describe older directions and some stale viewport assumptions; rendered truth must decide which rules are effective.

## Coherent composition refactors and exact file ownership

These are implementation batches after the shared tokens/shell are established. They are not independent visual directions.

1. **Current placement workbench** — `intern/active-entry.tsx`, `empty-intern-workspace.tsx`, `waiting-recruitment-summary.tsx`, `history-entry.tsx`. Lead with placement/next real action; a single stat strip, actual work queue and compact Sprint/context rail. For waiting/history, use one state-first heading and genuine evidence below it. Preserve all original content through flow or disclosure, not removal.
2. **Task and project workspace** — `product/intern-work.tsx`, `product/intern-entry.tsx` (presentation branches only), `intern/student-work-list.tsx`. One filter bar, compact collection, task brief + action pane + specifications/submission. Sprint selector/summary form one context strip; board cards are genuine task objects. These files also serve managed roles, so isolate own/student markup and keep shared logic signatures unchanged.
3. **Results and evidence** — `product/outcomes.tsx` student presentation, `intern/student-performance.tsx`, `intern/student-score.tsx`. Index collections have compact summary rows; detail pages retain complete official evidence. Score/balance/rate visuals use tokens and real data; ledger uses table. Do not modify public `Verify` or role-shared behavior incidentally.
4. **Communication, identity and integration** — `product/mentor.tsx`, `intern/student-github.tsx`, `participation/student.tsx`, student branches of `outcomes.tsx:Notifications`, shared `product/profile.tsx` in coordination with the parent. Use one split workbench pattern: actual collection/main task versus a lightweight context/help rail. Preserve every external integration and feedback state.
5. **Recruitment workbench** — `intern/onboarding/onboarding-shell.tsx`, `welcome-step.tsx`, `role-selection-step.tsx`, `role-card.tsx`, `scheduled-interview.tsx`, `interview-step.tsx`, `conversation-interview.tsx`, `recruitment-result.tsx`, `recruitment-policy.tsx`. Reuse core header/control/state tokens; no decorative mascot rail; appointment/interview/result layouts have different tasks but identical typography/control semantics. Leave guard/provider/API/scoring logic untouched.

Shared foundation files (`intern/student-ui.tsx`, student CSS, intern shell/sidebar/topbar, `workspace/*`, product primitives) need a single owner and centralized tokens before these batches. Avoid each page adding another override layer.

## Specific baseline risks for the implementation

- **Literal colors:** `student-score.tsx:12` builds tone from three HEX values; `empty-intern-workspace.tsx` includes literal SVG colors; `product/profile.tsx` includes literal SVG colors; `role-card.tsx` includes literal selected/unselected shadows. `student-experience.css` includes hundreds of raw color syntax matches (including legitimate current token definitions). Map actual values to central semantic tokens rather than blindly replacing all matches.
- **Width animation:** `student-experience.css:882`, `workspace.css:1349`, `onboarding-primitives.tsx:110` animate width. Use static native progress or transform/opacity; preserve accessible label/value equivalents.
- **Entrance duplication:** `student-reveal` is 320 ms while route frame is 240 ms and workspace adds another route entrance. Product should not choreograph every navigation. Existing reduced-motion/forced-colors rules must remain effective after cascade simplification.
- **Style bleed:** `outcomes.tsx`, `profile.tsx`, `intern-entry.tsx`, `intern-work.tsx` and GitHub connection components are used outside `/intern`. Keep role branches and component props, and coordinate shared edits.
- **Stale documentation in source:** waiting/onboarding comments describe fitting everything in one viewport, compact mascot and previous reference labels. Do not equate those comments with current rendered requirements; user now prioritizes readable natural flow at six widths.
- **Fixture versus real UI:** `ActiveInternWorkspace` and its mock KPI/PR/notification cards are imported by `src/test/intern-workspace-preview.tsx`, not the live `/intern` dashboard. Their snapshot-like tests do not prove live behavior. Runtime path is `InternWorkspace` → `ActiveEntry` or real waiting/history components. Preserve fixture code until a separate file-level retirement plan exists.
- **Auth and persistent shell:** do not remove embedded workspace fast path or re-mount provider on each page. Task/comment/composer drafts and keyboard focus must survive background refreshes.
- **Meaningful nulls:** performance/KPI code explicitly distinguishes missing data from zero; charts must continue to do so. Sent GitHub invitation is not accepted repository access. Agent advice is not official teacher grading.
- **Responsive baseline remains unverified by this audit:** structural breakpoints are numerous (560, 639, 700, 720, 760, 767, 900, 1023, 1100, 1180, 1280). Need actual captures at 375/480/768/1024/1280/1440 after foundation changes; narrow board/table scroll must not turn into hidden content.

## Implementation handoff — student presentation batch

The parent established `src/styles/tokens.css` and assigned student presentation ownership. The following changes are now in source, with public homepage `/` untouched:

- `intern/student-experience.css`: refactored existing rules in place to consume centralized semantic color, type, spacing, radius, elevation and weight tokens. Default panels/metrics/list rows are unboxed sections with deliberate dividers. Task/role/certificate objects retain bounded surfaces. Removed gradient backgrounds, repeated route/reveal entrances, status stripes, decorative ring styling and width transitions. Added compact placement, Mentor workbench, record collection, source/help disclosure and narrow-layout rules. Reduced motion and forced colors remain present.
- `intern/student-ui.tsx`: metric label and functional icon now share one compact line; metrics retain their existing props/values/accessibility. `student-score.tsx` now presents the official value directly with native progress for non-null values, rather than a decorative ring or hardcoded colors.
- `intern/active-entry.tsx`: real work queue leads the main column; removed duplicated per-metric completion bars and repeated focused-task completion summary. Current placement and actual Sprint context remain visible. Coaching steps moved into disclosure; the Mentor route link uses the existing functional icon instead of a robot image.
- `product/intern-entry.tsx`: compact unboxed Sprint context; project description and technologies now form one brief, with metadata beside it and preparation guidance in disclosure. Board handlers, DnD and role-specific branches are unchanged.
- `product/intern-work.tsx`: project package is accessible from a labeled disclosure ahead of the toolbar, leaving task controls/list as the working surface. Detail facts, progress, task history, comments, specifications and submission retain their existing contracts, identities and mutation flow. `intern/student-work-list.tsx` uses the shared semantic type/color/control language.
- `product/mentor.tsx`: one split conversation/chat workbench and a compact first-use state. No robot illustration. Prompt insertion, composer focus, task context, explicit send, retry history and archive behavior are unchanged.
- `product/outcomes.tsx`: evaluation criteria are an explicit expandable evidence section (open on detail), outcome records/financial summary/recommendation rows share section hierarchy, and all presentation utility colors/types use semantic tokens. Notification mutations, feedback and preference behavior were preserved. `Verify` now owns an `.app-surface` wrapper and plain fact rows; verification input/API/error/valid/revoked branches remain unchanged.
- `intern/student-github.tsx`: account/repository objects stay primary; repository workflow is a quiet expandable help section. History-aware actions remain intact.
- Onboarding presentation (`welcome-step`, `onboarding-shell`, role/interview/conversation/result components and primitives): removed large welcome/rail mascot calls and result header artwork; role technologies are compact text; results use official value/progress and evidence. Both answer-based and conversation-based interview modes, server schedule/attempt restrictions, saved drafts and decision logic remain unchanged. Progress display uses transform with accessible numeric equivalents rather than animating width.
- Legacy student preview presentation classes/colors were normalized to the same tokens without removing fixture components, data or tests. Live route behavior continues to use real APIs.
